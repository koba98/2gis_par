# 2GIS Full Catalog & Reviews Parser

Асинхронный парсер 2ГИС, который обходит **весь каталог региона (или всей страны)** — все рубрики или заданные запросы, собирает полные карточки филиалов, контакты и **все отзывы**, и складывает всё в PostgreSQL в отдельную схему (по умолчанию `twogis`). Защита от блокировок (ротация прокси и User-Agent, бэкофф) сохранена. Если API-ключ 2ГИС заблокирован — есть резервный канал: прямой сбор через реальный браузер (см. "Браузерный фолбэк" ниже).

## Как устроен полный обход

1. Регион ищется по названию (`region/search`), из его границ берётся bbox. Флаг `--country kz` обходит сразу все 19 регионов Казахстана (`region/list`).
2. Загружается рубрикатор региона (`catalog/rubric/list`, рекурсивно). Для каждой конечной рубрики в очередь `crawl_tasks` кладётся тайл размером с регион.
3. Воркер ищет филиалы внутри полигона тайла (`3.0/items`, `type=branch`). API позволяет пролистать не больше `page_size × max_pages` результатов — если найдено больше, тайл делится на 4 части и так далее до `--min-tile`.
4. После каталога для каждого филиала выгружаются все отзывы по `next_link`. Повторный запуск дособирает только новые отзывы.

Очередь хранится в БД: прерванный обход (Ctrl+C, падение сети) продолжается с места остановки.

## Файлы

- **`parser.py`**: `TwoGisCrawler`, обход региона, рубрик, тайлов и отзывов, парсинг ответов API.
- **`storage.py`**: работа с PostgreSQL (psycopg 3, async): UPSERT данных и очередь тайлов.
- **`sql/schema.sql`**: DDL таблиц, индексов и представления `v_branches`.
- **`client.py`**: `AntiBanHttpClient`: прокси, User-Agent, общий для всех воркеров троттлинг, бэкофф при 429/403; детектирует блокировку ключа (`ApiKeyBlockedError`).
- **`web_fallback.py`**: `BrowserFallback` — резервный сбор напрямую с сайта через реальный Chrome (Playwright), когда API-ключ заблокирован. См. "Браузерный фолбэк" ниже.
- **`main.py`**: CLI.

## Таблицы (схема `twogis`)

| Таблица | Что хранит |
|---|---|
| `regions` | регионы/города и их bbox |
| `rubrics` | рубрикатор: группы и конечные рубрики |
| `organizations` | организации (сети), объединяющие филиалы |
| `branches` | филиалы: название, юр. имя, адрес, этаж, район, координаты, рейтинг, график, атрибуты, полный `raw` JSON |
| `branch_rubrics` | связь филиал ↔ рубрика (с признаком основной) |
| `contacts` | телефоны, сайты, email, соцсети и мессенджеры |
| `reviews` | отзывы: рейтинг, текст, автор, лайки, фото, официальный ответ, полный `raw` JSON |
| `crawl_tasks` | очередь тайлов обхода и их статус |
| `v_branches` (view) | плоская выгрузка: филиал + рубрики + телефоны/сайты/email + число собранных отзывов |

В колонке `raw` (jsonb) хранится исходный ответ API, так что поля без отдельной колонки тоже не теряются.

## Установка

```bash
pip install -r requirements.txt
cp .env.example .env   # заполнить PG_DSN и ключи 2ГИС
python main.py init-db
```

Ключи API берутся на https://dev.2gis.com. Демо-ключ ограничен: страница до 10 элементов и не больше 5 страниц на запрос (это значения по умолчанию `--page-size 10 --max-pages 5`). С коммерческим ключом можно поставить `--page-size 50`.

## Использование

```bash
# Весь регион: все рубрики, все филиалы, все отзывы
python main.py crawl --region "Алматы"

# Вся страна разом: все регионы Казахстана, рубрики, филиалы, отзывы
python main.py crawl --country kz --workers 4

# Только некоторые рубрики (по подстроке названия)
python main.py crawl --region "Алматы" --rubric "Кафе" --rubric "Ресторан"

# По поисковым запросам вместо рубрикатора, в заданной области
python main.py crawl --region "Москва" -q "аптека" -q "клиника" --bbox 37.35,55.55,37.85,55.95

# Без отзывов; отзывы потом отдельно (только ещё не собранные)
python main.py crawl --region "Алматы" --no-reviews
python main.py reviews --only-missing

# Отзывы по всей стране отдельным проходом (например, после сбора каталога)
python main.py reviews --country kz --only-missing

# Начать обход региона заново
python main.py crawl --region "Алматы" --fresh

# При блокировке API-ключа — автоматически переключаться на прямой сбор
# через реальный браузер (см. "Браузерный фолбэк" ниже)
python main.py crawl --country kz --browser-fallback

python main.py stats
```

## Браузерный фолбэк (когда API-ключ заблокирован)

2ГИС может заблокировать ключ (`meta.error.type == "apiKeyIsBlocked"`, отдаётся
с HTTP 200 у Catalog API или HTTP 403 у Reviews API — `client.py` ловит оба
варианта и поднимает `ApiKeyBlockedError`). С флагом `--browser-fallback`
`main.py` перехватывает эту ошибку и на лету переключается на
`web_fallback.BrowserFallback`: открывает страницы 2ГИС в настоящем
системном Chrome через Playwright (техника из `dgis_stations_parser.py` —
обход заглушки "обновите браузер" реальным кликом) и перехватывает сетевые
ответы, которые сам сайт получает от `catalog.api.2gis.*` /
`public-api.reviews.2gis.*` собственным встроенным ключом/сессией — эти
JSON-данные разбираются теми же `parse_branch()` / `parse_review()`, что и
обычный путь через API.

```bash
pip install playwright   # 'playwright install' НЕ нужен — используется системный Chrome
python main.py crawl --region "Алматы" --browser-fallback
python main.py crawl --country kz --browser-fallback --browser-show   # показать окно браузера для отладки
```

Особенности:
- Каталог собирается по поисковым запросам сайта (`-q`), а не по bbox-тайлам
  API. Если `-q` не задан и рубрикатор недоступен (ключ заблокирован ещё до
  первого запроса), используется список общих категорий по умолчанию
  (`DEFAULT_BROWSER_QUERIES` в `main.py`) — покрытие хуже, чем через
  рубрикатор, но каталог собирается вообще без рабочего ключа.
- Отзывы фолбэк собирает через вкладку `/firm/<id>/tab/reviews` со скроллом
  и кликами "Показать ещё", перехватывая пагинацию тем же способом.
- **Ограничение**: сайт 2ГИС банит дата-центровые IP на уровне edge/CDN ещё
  до заглушки "обновите браузер" — показывает reCAPTCHA (`2GIS Captcha`) или
  `403 Forbidden`. `web_fallback.py` детектирует это и поднимает
  `CaptchaBlockedError` с понятным сообщением вместо тихого зависания.
  Запускайте `--browser-fallback` с обычного (не облачного/датацентрового)
  IP — с VPS в облаке он, скорее всего, не пройдёт антибот-проверку.
- Соответствие `region.name → slug` сайта (`https://2gis.kz/<slug>/...`)
  задано в `parser.REGION_SLUGS` (те же 19 slug'ов Казахстана, что в
  `dgis_stations_parser.REGIONS`). Для региона вне этого списка фолбэк для
  каталога/отзывов недоступен — в логе будет явное предупреждение.

## Параметры

Общие для всех команд:

| Аргумент | Описание | По умолчанию |
|---|---|---|
| `--dsn` | строка подключения PostgreSQL | env `PG_DSN` |
| `--schema` | схема для таблиц | env `PG_SCHEMA` или `twogis` |
| `--catalog-key` / `--reviews-key` | ключи API 2ГИС | env `TWOGIS_CATALOG_KEY` / `TWOGIS_REVIEWS_KEY` |
| `--workers` | параллельные воркеры | `2` |
| `--delay` | базовая пауза между запросами (общая на всех воркеров), сек | `1.0` |
| `--max-delay` | максимальный бэкофф при 429/403, сек | `30.0` |
| `--timeout` | таймаут HTTP-запроса, сек | `15.0` |
| `--proxies` | файл со списком прокси (см. `proxies.example.txt`) | нет |
| `--browser-fallback` | при блокировке ключа переключаться на сбор через браузер | выкл. |
| `--browser-show` | показывать окно браузера (по умолчанию headless) | выкл. |
| `--browser-max-pages` | лимит страниц сайта на один запрос в браузерном фолбэке | `50` |
| `-v` | DEBUG-логи | выкл. |

`crawl`: `--region` / `--region-id` / `--country` (одно из трёх, обязательно), `--bbox`, `-q/--query`, `--rubric`, `--page-size`, `--max-pages`, `--min-tile`, `--no-reviews`, `--fresh`.

`reviews`: `--region-id` / `-r/--region` / `--country`, `--only-missing`.
